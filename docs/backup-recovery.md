# 備份狀態與隔離復原

## 已提供的能力

現行程式使用 SQLite online backup，讀取包含已提交 WAL 的一致性快照。新副本必須通過唯讀驗證 worker 的 SQLite 一致性快速檢查 `quick_check`，才寫入成功歷史；同秒備份以 UUID 分辨。備份有界排隊，最多一個工作、兩個等待工作，超過會提示稍後重試。

原保留政策不變：自動備份 30 份、手動備份 10 份，以路徑安全且實際存在的副本計算；缺檔或異常紀錄不占用此配額。清理只處理安全的一般檔案，拒絕路徑穿越、連結與異常檔案；異常或缺檔紀錄會保留，可能使歷史紀錄數超過一般保留數量。這不是新增的臨床歷史刪除政策。

## 管理員檢查

管理員可讀 `/api/system/backup-health`：

- 最後嘗試、最後成功及最後失敗；失敗不會抹掉先前成功資料。
- 主要 DB／WAL 大小、已登記備份的可用／缺失／異常數及可用檔案大小。
- 最近副本驗證結果：`ok`、`failed`、`missing`、`unsafe`；沒有驗證時為空。
- 當前排隊狀態及保留清理需人工核對的警告。

`GET /api/system/backups` 維持原清單欄位，另帶 `fileExists`、`pathSafe`。`POST /api/system/backup` 建立手動備份，成功回傳檔名；忙碌回 503，其他失敗會保留失敗狀態。這些端點均為 admin 權限，沒有線上覆蓋還原端點。

`quick_check` 是 SQLite 一致性快速檢查，並確認副本可查詢；它不是完整 `integrity_check`，不等於醫療內容正確、院內網路備援存在或整套災難復原完成。

## 在隔離位置還原

先核對執行目錄與來源。使用專案指定的 Node 版本及已安裝的依賴，不複製別台電腦的 `node_modules`。本工具不需要啟動應用程式，不使用正式 DB_PATH，不會覆蓋任何既有目的目錄。

```powershell
node scripts/restore-backup.mjs --source "C:\isolated-test\backup.db" --target-dir "C:\isolated-test\restore-new"
```

請將範例替換成實際核對過的隔離位置。來源必須是一般 SQLite 檔案，不能是連結；來源不存在或毀損會失敗。目的父目錄須已存在，最後一層目錄必須全新。成功產生 `restore-new\dialysis.db`，並輸出 `quickCheck: ok` 與資料表數。工具先唯讀開啟來源，以 SQLite backup 讀取已提交 WAL，再對新副本執行檢查及查詢。

成功後，另在隔離環境核對預期日期、資料量及必要工作流程。若需要將副本投入正式使用，先安排維護時段，核對目前正式資料與還原版本間的新資料如何處理；本工具不會替你決定回退、切換 DB_PATH 或啟動服務。

現行正式 PM2 名稱為 `dialysis-server-angular`，目錄由 `ecosystem.config.cjs` 指定為 `D:\dialysis-app-angular`，實際資料與備份路徑仍以現場 DB_PATH／BACKUP_DIR 為準。不要沿用舊 Vue 的程序名稱、直接覆蓋資料檔或刪除 WAL/SHM 的教學。不要把 `npm run migrate` 的歷史匯入工具當作復原步驟。

## 本次驗證邊界

自動測試使用合成、暫存資料庫及全新隔離目的地，涵蓋並發檔名與排隊、備份失敗狀態、毀損／缺檔、權限、異常路徑保留，以及仍在 WAL 的已提交資料可從還原副本讀取。沒有讀寫正式病人資料，沒有對正式站執行復原或部署。

院內是否已有異機副本、VM 快照與監控仍需向維護單位核實；本機備份成功不是異機備援證明。正式容量基線、警示時限、異機副本與院內還原演練仍應依現場政策安排。
