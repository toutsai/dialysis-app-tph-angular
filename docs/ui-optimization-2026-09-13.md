# onsite-main-dev 介面優化與測試指南

日期：2026-09-13（台北）。依據前一份全專案 UI 評估，已分四批完成本輪操作可靠性、共用操作、流程導航及顯示效能優化，起點為 17603d9。

## 這次改了什麼

| 工作 | 實際操作改善 |
| --- | --- |
| 查病人與編輯 | 搜尋先列出姓名、病歷號及所在清單，再選查看、轉移或復原；搜尋本身不改資料。同名結果不會直接選第一位。新增與編輯中的內容有未存提醒，失敗保留表單。 |
| 病人清單 | 常用識別與重要狀態保留在主要欄位；履歷、醫囑直接可用，較少使用的操作放入「更多操作」。備註先顯示摘要，可展開完整閱讀；詳細欄位仍可切回。 |
| 病歷、調藥與申請 | 快速切換病人時，舊回應不會覆蓋新病人。醫師工作區處理未存內容；重大傷病長表單增加段落捷徑。 |
| 醫囑與多筆保存 | 四個透析醫囑入口防止連按重送。已寫入但畫面刷新失敗時會說明已儲存，避免重建。醫師班表及檢驗批次保存區分成功／失敗，只重試失敗項目。 |
| 排程與護理 | 日期切換採一致操作，顯示保存狀態；編輯與保存中的日期、病人歸屬受到保護。鍵盤可選床、取消及移動，仍使用原本的排床規則。 |
| 調班與工作日誌 | 從排程進調班時攜帶日期／病人條件，返回能延續日期。日誌增加段落捷徑與易取得的主要操作，原 PDF 及歷史版本功能保留。 |
| 交辦與視窗 | 建立交辦失敗不關窗、內容保留；主要視窗可用 Tab／Escape，巢狀選病人與確認窗依序回到原操作。 |
| 庫存總覽 | 管理者與書記可直接進入庫存總覽，單品明細保留盤點、每日需求、實耗與到貨資訊。 |
| 書記庫存作業 | 直接進作業行事曆；同一作業日期串起 HIS 核對、實體盤點、週補貨。網址、日期及草稿一起管理，取消切頁或載入失敗會保持一致。盤點資料未載完前鎖定輸入，避免覆蓋剛打的內容。 |
| 檢驗與 KiDit | 檢驗可篩選待填／未儲存及失敗項目，顯示篩選不刪除完整報表資料。KiDit 入口與患者列可鍵盤操作，載入失敗及未同步草稿有明確提示。 |
| 全站導航 | 增加授權角色的庫存捷徑，帳號與登出固定可見，選單能鍵盤操作。帳號密碼顯示按鈕、操作指南與焦點提示一併整理。 |
| 報表讀取 | 日／月／年及人力報表只讀必要日期區間，保留現行與歸檔排程的合併方式，完整結果與原查詢比對一致。 |
| 藥囑查詢 | 群組可切換清單／表格對照，個人可切換清單／月份對照；預設有資料品項，可顯示全部，Excel 保留完整資料及歷年自訂藥碼表頭。患者多筆匹配時明確選人，結果標題與匯出依成功查詢條件呈現。 |
| 手機閱讀醫囑 | 成功查詢後收合條件，可由「更改查詢條件」再次展開。患者姓名、病歷號、年份及匯出保持可見；清單內逐筆保留頻率、備註及日期。 |

已存在而保留的功能包括衛教待完成篩選、床邊大按鈕與 PIN 邊界、單品庫存原生明細、既有離線草稿／版本衝突、PDF／Excel 延遲載入及 Angular 路由延遲載入。沒有為了改版重新建立一套臨床計算或角色權限。

## 已量測的改善

同一份模擬患者及長備註、1280×720 畫面：首列高度由約 1,388 像素降到 96 像素，備註欄由約 25 像素增加到 285 像素。搜尋按鈕約 40 像素高，主要列操作約 37 像素高；390 像素窄版搜尋約 42 像素高，整頁沒有橫向溢出。

三年合成報表資料的實際 API 回傳量：日報由 1,461 筆／514,919 bytes 降到 2 筆／707 bytes；護理人力月報由 1,096 筆／566,633 bytes 降到 29 筆／14,994 bytes。這些是相同合成資料的讀取量比較，不代表院內實際耗時或使用者速度。

藥囑使用固定的 100 位患者 × 36 品項 × 6 個月，共 21,600 格合成資料比對，所有原有顯示字串完全一致。原本每次格式化約 7.61 毫秒；獨立量測新版建立含逐筆清單明細的顯示資料約 9.86 毫秒，之後讀取全部已整理字串約 0.34 毫秒。每組預熱 8 次、量測 21 次後取中位數。這是本機資料整理成本：首次建立較多，重複使用結果較省，不等同整頁或院內實際查詢速度。

另以真實瀏覽器查詢 100 位合成患者，預設有資料品項呈現 100 格藥品資料，全部品項為 1,200 格；兩者都保留 100 位患者，匯出仍為 100 列 × 16 欄。切換顯示不額外讀取醫囑。390 × 844 畫面中，收合查詢後清單及對照表的閱讀區各約 314 像素高。

## 建議你在測試站驗收

1. 病人清單：搜尋同名或病歷號、查看履歷、展開備註、切換詳細欄位；確認平日常用操作仍找得到。
2. 編輯病人或申請：先改一個欄位，再切人或離開；確認取消後內容保留。儲存失敗情境已由隔離測試驗證。
3. 排程：用鍵盤選床與取消，再做一次正常調班；檢查帶入的日期及患者是否符合你的工作方式。
4. 書記：從庫存作業選日期，核對 HIS、盤點、計算週補貨；切日期或返回時確認仍是同一個作業內容。
5. 管理者：由庫存總覽選某 AK，確認盤點量、每日預計／實際消耗與到貨資訊是否一目了然。
6. 醫師與護理：查看檢驗待處理／失敗篩選、KiDit 入口及醫囑顯示；核對慣用的單位、頻率及日期呈現。
7. 藥囑查詢：選定患者與年份，切換清單／月份對照、再顯示所有品項；下載 Excel 核對完整欄位。只調整搜尋條件但尚未查詢時，結果標題應維持原本的患者與期間。

## 主機拉回開發分支

沿用主機既有的測試資料庫設定，先做好一致性備份。Node 版本沿用專案 .nvmrc（22.23.2）。

```powershell
git fetch origin
git switch onsite-main-dev
git pull --ff-only origin onsite-main-dev
npm ci
npm ci --prefix angular-client
npm run build:angular
```

完成後以主機既有方式啟動測試程序。若沿用專案的隔離測試模式，可使用 `npm run start:review`；其設定依專案測試環境為準。這次前端修改不需執行 Firestore 匯入工具 `npm run migrate`。

通知較多時，側邊欄的多個區塊會爭用高度。以 20 筆合成通知重現，1280 × 720 視窗展開後臺管理後，常用選單縮至約 72 px。改為固定平台標題及底部帳號區，常用選單、後臺管理及通知共用中間捲動區，保留完整內容高度，且可捲至最後一筆通知。
