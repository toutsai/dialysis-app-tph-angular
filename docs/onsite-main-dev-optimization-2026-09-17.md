## 已實作

| 層面 | 改善 | 驗證重點 |
| --- | --- | --- |
| 歷史排程快取 | 相同日期及重疊批次共用尚未完成的請求；清除後舊回應無法填回快取 | 重疊請求、回應逆序、失敗重試、登出後重新載入 |
| 針劑清單快取 | 同日期／病人集合合併請求；併發載入狀態正確；過期與容量清理 | 空結果快取、TTL、容量上限、舊請求不干擾新請求 |
| 使用者名錄 | 清除後隔離舊回應與舊重試冷卻；成功空名錄也會快取 | 新舊登入競爭、Retry-After、失敗後重試 |
| 登入與刷新 | JWT 加入唯一識別；舊憑證失效和新 Session 寫入放在同一交易 | 同秒登入、連續刷新、資料庫故障回滾、SSE 通知只在提交後送出 |
| 用藥儲存 | PATCH／PUT 保留未傳欄位；明確傳空陣列仍可清空；不存在資料回 404 | 狀態修改不清空藥單、藥單修改不重設狀態、RBAC、錯誤輸入 |
| 即時病人統計 | 只讀當前病人，不再載入不需要的全部歷史 | 與既有分類／歷史回溯引擎比對相同結果 |
| 通知查詢 | 同次請求的重複作者只查一次，包含查無資料的作者 | 減少查詢次數；跨請求仍反映作者改名 |
| JSON 傳輸 | gzip 尊重編碼權重及 no-transform；保留 Express 序列化與 HTTP 行為 | CORS Vary、HEAD、ETag／304、204／205、循環資料錯誤 |
| 前端檔案服務 | 版本查詢改非同步讀檔；雜湊資源長期快取；缺少資源正確回 404 | 深層連結、重新建置偵測、未知 API JSON 404、不回傳錯誤的 Angular HTML |
| 維護流程 | 新增 `npm run verify` 與 Windows／Ubuntu CI；忽略本機 review 資料目錄 | 語法、回歸、正式建置、隔離 smoke 串接執行 |

## 可重現的效能證據

- `tests/patient-census-performance.test.mjs`：75 位合成病人、6,000 筆歷史；即時統計讀取由 **6,075 筆降為 75 筆**（減少約 98.8%），計數結果一致。執行時間受硬體與負載影響，測試以結果及讀取量為判定依據。
- `tests/medication-query-integrity.test.mjs`：90 筆通知、2 個舊作者識別；作者查詢由 **90 次降為 2 次**，不使用跨請求快取。
- `tests/frontend-store-cache.test.mjs`：相同針劑查詢同時執行只發出 **1 次請求**；歷史排程重疊批次只補讀尚未取得的日期。

## 驗證方式

```text
npm ci
npm ci --prefix angular-client
npm run verify
```

`verify` 依序執行語法檢查、全部回歸測試、Angular 正式建置、端到端 smoke。CI 已設定使用鎖定依賴，在 Windows／Ubuntu 執行同一指令；不需要正式站密碼或病人資料。本次下表為本機 Windows 的實跑結果，並非宣稱 GitHub 上兩個平台已執行通過。

修改前基準：smoke 74/74；回歸測試 153 通過、1 失敗、1 跳過。原有失敗為護理日誌測試漏載正式輔助方法，本次補齊測試環境，保留原斷言。

## 範圍與限制

- 測試使用合成資料與記憶體／暫存資料庫；未操作正式病人資料、未執行正式資料遷移、未部署院內站台。
- 保留既有畫面流程、透析頻率、KiDit 規則及病人分類定義；未進行框架大版本或 Excel 解析器更新。
- 既有 SheetJS 升級檢查仍為跳過狀態；不能將這次驗收視為依賴安全稽核完成。
- 本次處理 Session 換發的原子性，未重新設計所有 HTTP 認證政策；原有黑名單讀取失敗處理及 HTTP／SSE 驗證一致性仍適合另作專項檢查。
- 合成案例證明特定查詢與請求減量，不代表已量測全院正式負載或完成所有頁面的人工驗收。
