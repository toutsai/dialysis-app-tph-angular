# onsite-main-dev 修正內容

基準：`onsite-main@6a10fc2`。此分支供獨立測試，不會合併或部署正式站；既有 `dev` 分支保留。

| 原審查項目 | 修正後行為 |
| --- | --- |
| R1 醫囑欄位遺失與兩次儲存競爭 | 一次請求、同一交易保存目前醫囑與完整歷史；省略欄位保留，明確空值可清空。必要的今日快照、模式歷史及 CVVHDF 例外清理一起成功或回滾，成功後才發通知。 |
| R2 週表遺失欄位／互相覆寫 | 保存完整床位資料，帶入讀取版本；衝突保留草稿。尚未建立的排程用獨立版本標記，保護首次存檔競爭。 |
| R3 空排程與暫停失效 | 已存在的空排程維持為空；新日期生成時一併處理有效例外。 |
| R4 跨日移班改派／重建 | 來源、目的及連動日期一起重建和檢查衝突；凍結來源無法復原的新衝突會整筆拒絕，保留原場次。 |
| R5 病人刪除權限繞過 | 一般更新也檢查刪除／復原的狀態變更權限，完整表單帶回未變更狀態仍可正常編輯。 |
| R6 即時通知／延遲回應覆蓋草稿 | 載入和儲存各自追蹤日期與編輯版本；較晚完成的舊讀取不覆蓋新編輯，存檔期間的新修改保留未儲存狀態。 |
| R7 預約總表更新半套成功 | UPDATE_BASE_SCHEDULE_RULE 的病人、總表、未來排程與完成狀態同一交易；失敗回滾後記錄失敗。 |
| R8 設備與職稱權限 | 五個設備寫入入口對齊既有 admin／viewer 設計；職稱改變撤銷舊登入 session。 |

Excel 套件升至官方 0.20.3，固定隨庫封裝及校驗值；保留瀏覽器按需載入，並驗證舊 XLS／XLSX、Big5 及前後端輸出互讀。執行環境固定 Node.js 22.23.2，加入可重現的測試入口與 Windows／Linux GitHub workflow。

## 驗證與主機驗收

新增測試涵蓋上述資料一致性、角色矩陣、故障回滾、延遲回應及 Excel 相容性。API 測試採合成暫存資料庫；排程測試採記憶體資料庫。自動測試不使用正式資料與 HIS。

請依 [主機測試步驟](onsite-main-dev-testing.md) 在新目錄安裝、建置並啟動。`npm run start:review` 使用獨立 `data-dev`、隨機本地管理員密碼與 `127.0.0.1:3003`，關閉排程。正式合併前仍需現場操作驗收。

## 後續另行安排

- HIS 傳輸介面、安全整合及院內端到端驗證。
- Angular 大版本升級、現有 CSS 大小警告與 PDF 相依套件 CommonJS 警告。
- 以院內實際資料規模量測查詢、排程與介面效能，再決定進一步拆分或優化。
- 其他預約類型的交易設計另行審查；本次保留既有生效日、今日凍結、逾期不自動補跑及 KiDit 排除規則。
