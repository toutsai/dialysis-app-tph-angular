# 制度檔維護協議

這套檔案（CLAUDE.md + docs/claude/ + .claude/agents/）的價值取決於它保持正確、精簡。本協議規定未來 session 怎麼安全地更新它們。

## 1. 權限分級：哪些可以自己改、哪些要先問

**可自行改（不必問使用者）**：

- 修正**事實錯誤**：路徑失效、行數過時、指令改名、結構清單漏新檔——改之前要先驗證新事實（實際跑過/讀過），commit message 說明依據。
- 在 `architecture.md` 補**新子系統的描述**（新功能上線後）。
- 在本檔 §3 規定的位置**追加教訓**。
- 更新 `CLAUDE.md` 文件路由表（新增了值得路由的檔案時）。

**必須先問使用者**：

- 改動**規則本身**：delegation 的升降級路徑、judgment 的判準、verifier 的驗收規則、陷阱清單的任何一條（新增陷阱可以，**刪除或放寬**要問）。
- 刪除任何制度檔或 archive 內容。
- 改變檔案結構（搬家、改名、合併）。

判斷方法：改「事實」不用問，改「規範」要問。分不清就當規範。

## 2. 改前必做

1. 備份：`cp <檔> docs/claude/archive/<檔名去掉.md>-$(date +%F).md`（同日多次改同檔，沿用當日既有備份即可，不必重複備份）。
2. 改完派 `verifier` read-back：確認改動落地、沒有誤刪其他段落、路徑引用仍有效。
3. commit message 用 `docs(claude): ...` 前綴並說明**為什麼**改。

## 3. 踩坑教訓寫回哪裡、用什麼格式

每次踩到「文件沒寫、害你走錯路」的坑，修完問題後**當場**寫回，位置按類型：

| 教訓類型 | 寫到 | 格式 |
|----------|------|------|
| 專案地雷（改了 X 會壞 Y、隱藏耦合、刻意決策） | `CLAUDE.md` ⚠️ 陷阱清單 | 一條 = 一行斷言 + 一句話原因/出處 |
| 子系統知識（行為細節、資料流） | `architecture.md` 對應節 | 併入現有條列，不開新章 |
| 派工失敗模式（某類任務該用什麼模型/怎麼拆） | `delegation.md` 對應節 | 併入表格或條列 |
| 判斷失誤（該問沒問、該停沒停） | `judgment.md` 對應判準 | 加成新的正例/反例（取代舊的更好） |
| 一次性脈絡（這次改了什麼、為什麼） | commit message / PR 描述 | 不進制度檔 |

**格式鐵律**：教訓 = 可執行的斷言（「X 時做 Y」），不是敘事（「上次我們遇到...」）。寫完自問：一個沒看過這段歷史的模型，讀這一行能照做嗎？

## 4. 長度預算與精簡時機

| 檔案 | 預算 | 超過時 |
|------|------|--------|
| `CLAUDE.md` | ~150 行 | 細節下放到 docs/claude/，只留斷言+指標 |
| ⚠️ 陷阱清單 | ~12 條 | 合併同類、把「已被程式碼防呆」的條目移到 architecture.md |
| `architecture.md` | ~200 行 | 過時小節整節移 archive |
| 其他制度檔 | ~150 行 | 同上 |

**已完成的計畫不留在 CLAUDE.md**：任何「計畫/待辦/狀態表」在完成當天移入 `docs/claude/archive/`（這是本制度誕生的第一原因——舊 CLAUDE.md 曾有 170 行已完成的遷移史料且自相矛盾）。

精簡是刪過時與重複，**不是**壓縮成只有強模型讀得懂的密文。刪任何一條規範前先過 §1 的權限分級。

## 5. 固定不變的邊界

- `AGENTS.md` 永遠只是指向 CLAUDE.md 的路標，不在那裡加內容。
- `docs/claude/archive/` 只進不改（append-only）。
- `docs/claude/00-diagnosis.md` 與 `letter.md` 是歷史快照，不更新（新的診斷另開新檔）。
