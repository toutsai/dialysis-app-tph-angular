# 給未來 session 的信（2026-07-06，Fable 5 制度建立 session）

使用者沒問、但你在這個環境工作前最該知道的三件事，以及這套制度最可能的死法。本檔是歷史快照，不更新。

## 三件最重要的事

### 1. 這裡沒有任何安全網：無 CI、無測試、無 staging，而下游是正在跑的醫院

- repo **沒有** `.github/workflows`、沒有單元測試。你 merge 的東西不會被任何機器攔下。
- 部署是**人工**的：使用者把檔案複製到院內 Windows VM 的 `D:\dialysis-app\`（非 git repo）再 PM2 重啟。所以 (a) merge ≠ 上線，不要說「已部署」；(b) 你是最後一道防線，`judgment.md` §2 的完成定義不是儀式，是唯一的攔截點。
- 最高風險產物是 **schema migration**（`src/db/migrate.js`——伺服器每次啟動自動跑在正式臨床資料上，寫錯一次就中）與**排程同步邏輯**（錯了會讓病人排錯床）。動這兩處，一律走 delegation.md §6 的第二意見流程。
- 本地驗證不必碰真資料：`scripts/create-today-mock-db.cjs` 能從現有 DB 產出「今日模擬資料庫」（床邊儀表板 PIN 預設 `1234`），`scripts/reset-passwords.cjs` 可重設測試密碼，smoke test 會自建帳號（`codex_smoke_` 前綴）。優先用這條路。

### 2. 時區與日曆是這個系統的隱形殺手

- 業務時區是 Asia/Taipei，但你所在的雲端容器多半是 UTC——**你本機跑出來的「今天」可能跟醫院的「今天」差一天**（台北早上 8 點前，UTC 還是前一天）。凡是日期相關的驗證，明確用 `utils/dateUtils.js` 的函式或設 `TZ=Asia/Taipei` 再跑。
- 日曆規則有既定裁決，別憑直覺重新發明：Q{N}W 針劑用**日曆週且週日起算**（commit c75b941 特地修過）；預約變更在每日 **01:00** 台北時間套用；排程同步展望 60 天。改任何日期邏輯前先讀 `architecture.md` 對應節。

### 3. 使用者是單人維護者，決策脈絡都在文件裡，先考古再動工

- 溝通用繁體中文。這位使用者會把未完成需求寫進 `docs/2026-05-08-follow-up-todos.md`、把決策脈絡寫進 handoff 檔——**動一個功能前先查路由表裡對應的檔**，不然你會重複提案已被否決的東西，或撞上「看起來是 bug 其實是刻意決策」（KiDit 排除「更改模式」就是最典型的例子）。
- 這個 repo 的分支模式：預設分支是 `onsite-main`，工作分支 `claude/*`，push 後開 draft PR。
- 使用者願意投資制度（本 session 就是證明）。踩到新坑，照 `maintenance.md` §3 寫回去，他會買單。

## 這套制度最可能的退化方式與預防

1. **CLAUDE.md 再度長胖**（最可能）。每個 session 都想「把這次學到的塞進 CLAUDE.md」，兩個月後回到 300 行史料。→ 預防：maintenance.md §4 的長度預算是硬限制；教訓按 §3 的分流表寫到對應檔，CLAUDE.md 只收「陷阱斷言」。已完成的計畫**當天**移 archive。
2. **規則被默默放棄**。派工三件套、verifier 驗收在小任務上顯得囉嗦，session 開始跳過，三週後整套制度變裝飾。→ 預防：規則本身已設門檻（<800 行自己讀、1–2 檔小改自己動手），小事本來就不必走全流程；若某條規則反覆造成無謂成本，正確動作是**帶著案例向使用者提修改**（maintenance.md §1：改規範要問），不是靜默忽略。
3. **事實腐化**。行數、路徑、指令會隨程式碼演進失準，文件從「可信」變「大概對」，然後沒人再查它。→ 預防：碰到不準的事實**當場修**（maintenance.md §1 授權自行改事實，不用問）；verifier 驗收制度檔改動時順檢引用路徑是否存在。
4. **verifier 被餵敘事變橡皮圖章**。實作者把「我做了什麼」的長篇說明塞給 verifier，它就會順著敘事打 PASS。→ 預防：驗收派工只給「宣稱 + 驗收條件 + 大致檔案範圍」三樣（prompt-templates.md 最後一節的格式），verifier 定義裡已禁止採信宣稱。
5. **模板複製突變**。模板被反覆複製改寫，驗收條件與回報合約段落逐漸掉光。→ 預防：模板開頭那行「不要刪掉這些段落」是給你的；發現派工品質下滑，回 prompt-templates.md 重新對照原版。
