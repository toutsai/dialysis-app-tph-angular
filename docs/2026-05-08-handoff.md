
### 2. `localhost:3000` 顯示找不到 `dist/index.html`

症狀：

```json
{"error":true,"message":"ENOENT: no such file or directory, stat '...\\dist\\index.html'"}
```

原因：

- Express 會服務 `dist/`，但 Angular production build 尚未產生 dist。

避免方式：

```powershell

```

### 3. Angular build 在 Codex sandbox 內常出現 `spawn EPERM`

症狀：

```text
An unhandled exception occurred: spawn EPERM
```

處理方式：

- 同一個 build 指令需用 escalated shell 重跑。
- build 成功時仍會有既有警告：
  - `daily-log.component.css` / `nursing-schedule.component.css` CSS budget exceeded。
  - `canvg` / `html2canvas` / `quill-delta` CommonJS warnings。
- 這些目前是既有警告，不等於 build failed。

### 4. 首透精靈曾出現 500 / 409 / `closeFirstDialysisPlan is not a function`

症狀：

- `POST /api/schedules/first-dialysis-plan` 500
- `POST /api/patients` 409
- 前端 console：`closeFirstDialysisPlan is not a function`

原因與修正方向：

- 前後端方法命名與 modal 關閉流程不一致。
- 新增病人遇到 MRN/id 衝突時會回 409，這是資料衝突，不是首透 API 本身必然失敗。
- 首透日期用 `toISOString()` 會被 UTC 影響，導致加洗日期錯一天。
- 後端如果 daily schedule 尚未生成，不能只查 schedules table 判斷空床，要能從 master schedule 生成目標日狀態後再判斷。

避免方式：

- 日期計算使用 `angular-client/src/utils/dateUtils.ts` 與 `src/utils/dateUtils.js` 的 Taipei helper。
- 不要用 `toISOString().split('T')[0]` 當台北日期。
- 首透 plan 儲存後要同步更新本地 patient store，否則同 session 第二次打開讀不到剛剛的設定。

### 5. 工作日誌歷史鎖定只改前端不夠

症狀：

- 前端看似可編輯，但儲存時後端回 `423 DAILY_LOG_LOCKED`。

原因：

- `daily-log.component.ts` 有 `isPageLocked`。
- `src/routes/nursing.js` 的 `PUT /daily-logs/:date` 也有後端鎖定。

避免方式：

- 權限規則要前後端同時改。
- 目前規則：過去日期只有 admin 可寫；editor 仍鎖定。

### 6. 登出清 storage 不等於清 Angular 記憶體狀態

症狀：

- 登出後再登入，日期仍是上次操作日期。

原因：

- `DateStateService` 是 Angular app runtime 記憶體，不在 localStorage/sessionStorage 裡。

避免方式：

- 登出時呼叫 `DateStateService.clear()`。
- 目前已在 `AuthService.clearBrowserStorage()` 中處理。

### 7. 後端改動需要重啟，前端 dist 改動通常重新整理即可

判斷：

- 修改 `src/routes/*.js`、`src/services/*.js`：需要重啟後端。
- 修改 Angular 檔案並已 build：瀏覽器重新整理；若看到舊 bundle，按 `Ctrl + F5`。

### 8. 不要把本機 DB 變動當成一般程式碼一起 commit

- 工作日誌：
  - 非 admin 選今天以前日期，應只能檢視。
  - admin 選今天以前日期，應可編輯與儲存。

  - 登出再登入後，每日排程/統計日期不要停在上次日期。

  - 行距保留緊湊。
